# 0004. Стейдж живёт внутри GitHub Actions

Дата: 28.09.2026
Статус: принято Настей

## Контекст

ADR 0002 оставил место стейджа на уровень Л3. Условие оттуда же: сборка одна, на стейдж
и в прод уезжает один и тот же артефакт.

У GitHub Pages один сайт на репозиторий. Второй репозиторий под стейдж даёт адрес
`/landing-voda-danang-stage/`, а собранные страницы ссылаются на файлы от корня
`/landing-voda-danang/`. Такой стейдж либо требует пересборки под свой адрес, что запрещено
гейтом G3, либо грузит файлы с прода, и тогда изоляции нет.

Внешний хостинг с публичным адресом (Cloudflare Pages) решает это, но требует аккаунта
и токена. Показывать стейдж некому: заказчик вымышленный.

## Решение

1. Артефакт собирается один раз, в `stage.yml`, с конфигом прода: `site.tar.gz` плюс его
   SHA-256.
2. Стейдж это тот же архив, распакованный в раннере и отданный `scripts/serve-site.ts`
   под тем же путём, что на Pages. На нём идут все e2e, Lighthouse и проверка отката.
3. Прод (`prod.yml`) скачивает архив из прогона стейджа, сверяет SHA-256 и выкладывает
   на Pages только после подтверждения Насти в окружении `github-pages`.
4. После выката ставится тег `v<версия из package.json>` и выпускается релиз с тем же
   архивом. Версия, которая уже выпускалась, в прод не идёт: гейт падает до выката.
5. Откат (`rollback.yml`) выкладывает архив из релиза нужного тега. На стейдже откат
   проверяется так: архив прошлого релиза поднимается и проходит smoke.
6. `config/stage.yml` остаётся пустым, `build:stage` убран: у стейджа нет своей сборки.
7. `noindex` на проде остаётся (ТЗ 7.5). SEO в Lighthouse меряется без аудита
   `is-crawlable`, он красный по замыслу, остальные проверки SEO считаются как обычно.

## Что это меняет

1. У стейджа нет публичной ссылки. Посмотреть сборку глазами можно локально:
   архив из артефактов прогона и `npm run serve:site`.
2. Изоляция полная: стейдж живёт минуты и исчезает вместе с раннером, у прода нет с ним
   общих ресурсов.
3. Появится реальный заказчик, которому нужен стейдж по ссылке, решение пересматривается
   в пользу внешнего хостинга.
