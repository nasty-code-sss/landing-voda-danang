# 0008. KakaoTalk для корейского, WeChat для китайского

Дата: 28.09.2026
Статус: принято Настей

## Контекст

Корейская и китайская версии (ADR 0007) отправляли заказ в WhatsApp, Telegram и Zalo.
У корейцев основной мессенджер KakaoTalk, у китайцев WeChat. Задача из второй очереди ТЗ,
раздел 12, пункт 1.

Что проверено до кода, 28.09.2026:

1. KakaoTalk. Официальный JavaScript SDK Kakao 2.8.0 открывает чат с каналом бизнеса
   по адресу `https://pf.kakao.com/<ID канала>/chat` (функция `requestChat`, константа
   `CHANNEL`). Параметра с текстом сообщения нет ни в исходнике SDK, ни в справочнике
   `Kakao.Channel.chat()`: там единственный параметр `channelPublicId`. ID канала начинается
   с `_`, так он выглядит в адресе канала (документация Kakao Talk Channel).
2. WeChat. Ссылки на чат с личным аккаунтом по WeChat ID нет, прежняя схема
   `weixin://dl/chat?<ID>` отключена. Ссылка на чат есть только у WeChat Customer Service
   (корпоративный WeCom): `https://work.weixin.qq.com/kf/<id>`, она работает лишь в WeChat
   на телефоне, на компьютере просит открыть её в браузере телефона. Параметр `scene_param`
   уходит бизнесу в событие, а не в поле ввода. Правила WeChat ID из справки WeChat:
   6-20 знаков из букв, цифр, `_` и `-`, первый знак не цифра.

## Решение

1. KakaoTalk устроен как Zalo: нажатие копирует заказ в буфер и открывает чат канала.
   В корейской версии он первая кнопка.
2. WeChat, вариант Насти: ID и QR-код на странице. Нажатие копирует заказ и раскрывает
   под кнопками блок из двух шагов: добавить контакт по ID (кнопка «скопировать ID») или
   по QR-коду, потом вставить заказ в чат (кнопка «скопировать заказ», потому что копия ID
   вытесняет заказ из буфера). В китайской версии WeChat первая кнопка.
3. Тот же ID с QR-кодом стоит в подвале под якорем `#wechat`. Туда ведёт кнопка WeChat
   без JavaScript и кнопка WeChat в блоке для хозяев квартир.
4. QR-код рисуется при сборке в SVG библиотекой `qrcode-generator` (MIT, без зависимостей),
   в браузер она не попадает. Что зашить в код, задаётся в `contacts.wechat_qr`: это адрес
   из «Мой QR-код» заказчика в WeChat.
5. Ссылки мессенджеров в конфиге стали шаблонами с `{contact}`
   (`https://pf.kakao.com/{contact}/chat`): у KakaoTalk ID стоит в середине адреса.
6. Вариант с WeChat Customer Service не взят: он требует корпоративный WeCom у продавца
   и не работает на компьютере.

## Что это меняет

1. Два новых сценария приёмки: 19 (KakaoTalk) и 20 (WeChat).
2. На картинке превью у `ko` и `zh` четыре мессенджера, названия на языке страницы, поэтому
   куски шрифта Noto подбираются и по ним. Кнопки на картинке переносятся на новую строку,
   а не сжимаются.
3. Для боевого запуска у заказчика нужны: ID канала KakaoTalk, WeChat ID и ссылка из его
   QR-кода WeChat. Сейчас в конфиге демо-заглушки.
4. Предположение, не проверено: заказчик из Вьетнама может завести канал KakaoTalk без
   корейской регистрации бизнеса. Проверяется при заведении канала.
5. Предположение, не проверено на настоящем коде: личный QR-код WeChat хранит адрес вида
   `https://u.wechat.com/...` (так пишут сторонние разборы, официального описания нет),
   поэтому демо-заглушка такого вида. Проверяется сканером на QR-коде заказчика. Сам код
   на странице проверен: снимок из браузера OpenCV и zxing-cpp читают как адрес из конфига.
