# 0002. Контуры статического сайта без Helm

Дата: 27.09.2026
Статус: принято Настей

## Контекст

Стандарт (`architecture.md`, раздел 4) требует три изолированных контура со своей базой,
ключами и доменом, а особенности развёртывания переопределять через Helm.

У лендинга нет сервера, базы, ключей и контейнера. Это набор статических файлов.
Helm описывает развёртывание в Kubernetes и здесь переопределять нечего.

## Решение

1. `dev`: локальная сборка и предпросмотр на машине разработки.
2. `stage`: отдельный адрес предпросмотра. Где именно, решается на уровне Л3.
3. `prod`: GitHub Pages публичного репозитория.
4. Отличия контуров только в `config/<контур>.yml`: адрес сайта, флаг `noindex`, аналитика,
   контакты. Каталога `deploy/helm` в проекте нет.
5. Сборка идёт один раз в GitHub Actions. На стейдж и в прод уезжает один и тот же артефакт,
   в прод только после ручного подтверждения Насти. Правила защиты развёртывания на бесплатном
   тарифе доступны для публичных репозиториев
   (https://docs.github.com/en/get-started/learning-about-github/githubs-plans).

## Что это меняет

1. Гейты G0-G3 остаются как в стандарте, меняется только площадка.
2. Проверка изоляции: удаление стейджа не трогает прод, потому что это разные адреса
   и разные развёртывания одного артефакта.
3. Если у сайта появится сервер (приём заказов, подписка), решение пересматривается.
